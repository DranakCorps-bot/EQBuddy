## §3 The Founder amendment — first-open prompt vs TEL-001

TEL-001 as signed says *"No first-run prompt, no nag."* The Founder's
2026-09-22 word authorizes a **one-time first-open prompt** ("help improve
EQBuddy"). That is a direct amendment to TEL-001 by the requirement's owner,
and this plan carries it as such — named, not smuggled:

- The prompt appears **once**, on first open of an Evolved build carrying
  TEL-PR3. Declining (or dismissing) leaves telemetry OFF and the prompt
  **never returns** — a re-ask would be the nag TEL-001 still forbids.
  Accepting flips the same setting the Options toggle owns.
- The prompt is a **door to the one consent policy module**
  (`UI.Shared/TelemetryHeartbeat.cs`), never a second consent path — trap 47
  binds exactly as the Sep 5 plan wrote it: one policy module decides
  consent + cadence, every send path goes through it. The prompt writes
  `AppSettings.TelemetryEnabled` through the same writer, and a
  "prompt already shown" flag is a new `AppSettings` key with its
  `DeadSettingTests` row.
- The prompt shows **the entire payload in its own copy** (TEL-001's toggle
  rule, applied to the new surface) and links the Options row where the
  decision can be reversed.
- **Copy and shape go through Bevel pre-design** — already required before
  TEL-PR3, now covering the prompt as well as the toggle; consent copy is
  exactly what Bevel catches overpromising or burying. Helm last-looks the
  copy at TEL-PR3.

Everything else in TEL-001 stands: OFF on every install until the player
turns it on, opt-out destroys the install id, re-enabling mints a fresh one.

## §4 Launch sequencing — the declared slice sequence

The Sep 5 "not now / idle seats only" section is spent; this replaces it.
Four slices, in order, each starting when the previous merges green
(`build-and-test` + `e2e-windows`), signed once for the whole sequence:

1. **TEL-PR1 — requirement page** (docs only, this repo). `route: routine`.
   `docs/v2/telemetry.md` carrying TEL-001..006 **as amended by §3**, the
   payload JSON, cadence, retention table, delete contract, and clearly
   marked DRAFT replacement copy for README and SECURITY.md so TEL-PR4 is a
   copy-move. Docs only, no product surface — the one slice Jr could carry.
2. **TEL-PR2 — backend** (own public repo `DranakCorps-bot/eqbuddy-telemetry`,
   created only when this slice starts). `route: hard` — a new public repo
   under the project's name and the store of the off-machine data.
   Cloudflare Worker + D1 per the Sep 5 plan: `POST /heartbeat`,
   `POST /delete`, cron rollup to public `metrics.json`, 90-day raw purge,
   per-id rate limiting, tests for delete/retention/rollup. Free tier; the
   moment it needs a paid plan is a David money ask, then.
3. **Bevel pre-design pass** (not a PR): toggle, first-open prompt, consent
   copy, status line, delete affordance. Ask filed in `BEVEL.md` when
   TEL-PR2 is underway. TEL-PR3 does not start before Bevel's pass returns.
4. **TEL-PR3 — client** (this repo). `route: hard` — the surface that sends
   bytes off the machine. Exactly the Sep 5 scope plus §3's prompt:
   `UI.Shared/TelemetryHeartbeat.cs` pure policy (unit-tested, no network),
   one thin sender, `AppSettings.TelemetryEnabled` (default false) +
   `TelemetryInstallId` (nullable, cleared on disable) + the prompt-shown
   flag, Options toggle + payload copy + "last heartbeat" status line +
   delete button, the first-open prompt. Guards, each **prove-failed**
   before its eight greens: the TEL-002 key-set test (serialized keys equal
   exactly `installId`/`appVersion`/`os`), the single-endpoint source
   scanner (one module holds the literal, no second `HttpClient` reaches
   it), the E2E dump fact (`telemetry=off sends=0` on a default profile),
   and an E2E/unit fact that a declined prompt never re-shows. Options shot
   in both toggle states, staged OFF + "never sent" (trap 23).
5. **TEL-PR4 — the public face** (this repo, **in the launch release
   only**). `route: hard` — consequence item 3; Helm signs the copy.
   README/SECURITY flip to the TEL-PR1 drafts, `docs/Telemetry.md`,
   README metrics block with the labeled downloads row, `WhatsNew.json`
   entry. Rides the launch/channel-open release David already gates.

**Boundary.** Heartbeat only — TEL-006's scope freeze binds: no crash
reporting, no feature events, no session stats, no error strings. A fourth
payload field, any new event kind, or any change to retention/delete is a
**new plan with its own gate walk and Helm SIGN** — that escalation is the
seam this sequence-wide SIGN rests on. Play Console stays OFF throughout.
