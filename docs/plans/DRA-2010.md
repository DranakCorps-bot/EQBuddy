## 1. The on-disk states cannot tell the two kinds of "off" apart. A fourth key is needed

Measured on `main` at `c44c0ea8` (`TelemetryHeartbeat.cs` 94–142):

| Writer | `PromptShown` | `Enabled` | `InstallId` |
|---|---|---|---|
| old build's "Not now" / Esc / ✕ (`Decline`) | true | false | null |
| v2.0.6 notice's **Turn off** (`Decline`) | true | false | null |
| v2.0.6 Options toggle off (`OptOut`, after the notice's `OptIn`) | true | false | null |
| confirmed delete (`DeleteConfirmed` = `OptOut`) | true | false | null |

All four rows are byte-identical. The card's acceptance 1 (old "Not now" goes ON, a v2.0.6+
explicit off stays OFF) **cannot be read from today's three keys**, and `LastSeenVersion`
does not help either: an old "Not now" user who has opened v2.0.6 carries `2.0.6` too.

**So D1 adds one key**, `TelemetryOffByChoice` (bool, default false), on `AppSettings` beside
the other three, written only through `TelemetryHeartbeat` (trap 47):

- `Decline` (the notice's Turn off), `OptOut` (toggle off) and `DeleteConfirmed` write it
  **true**. `OptIn` writes it **false**.
- **The rule:** `PromptShown && !Enabled && !OffByChoice` is a *legacy off*. It is treated as
  never answered: the notice shows once, and closing it (OK, Esc, ✕, Alt+F4) writes `OptIn`,
  exactly DRA-1980's close rule. `OffByChoice = true` stays off and never sees the notice.
- This retires DRA-1980 §1's "no fourth key". Helm's C-1 §8.3.1 three-key rule was written
  for an opt-in client. The Founder's order is what changes it, and the C1 walk is where the
  change gets argued. `DeadSettingTests` (trap 20) gets a writer and a reader in the same
  commit. No persisted migration: the reading happens at decision time (trap 55).

**Decided, and D1 logs it in `DECISIONS.md`: the v2.0.6 window is read as legacy off.**
Anyone who turned telemetry off *in v2.0.6* (tagged 2026-10-18 11:08 CT, so a window of hours
to days before v2.0.7) wrote the same bytes as a "Not now", and v2.0.7 shows them the notice
again. The default could have gone the other way: leave every `PromptShown && !Enabled`
profile off, which keeps the v2.0.6 promise exactly and misses the Founder's whole point (past
"Not now" users stay uncounted). Landed on the notice, because:
1. nothing is sent before the notice has been on screen (DRA-1980's rule, unchanged);
2. Turn off on that notice is one click and writes `OffByChoice = true`, so it is final from
   then on;
3. the notice gains **one extra sentence for this cohort only** (the legacy-off case, not a
   never-answered install): *"If you turned this off in the last version, choose Turn off
   again. That version could not save your choice in a way this one can read."* Wording is
   D1's, in `TelemetryCopy`; the sense is fixed here.
Reviewer, Challenger or Helm can veto at the last look. The veto (keep v2.0.6-era offs off)
would also keep every old "Not now" off, which is the Founder's order reversed, so a veto goes
back to the Founder as a ranked ask, not a quiet one-line change.

## 2. D1 — the client, the notice copy, the requirement text, What's new

**Consent rule (`TelemetryHeartbeat`, still the ONE policy).**
- `DecidePrompt` gets the legacy-off case above. Its outcome is the same notice and the same
  close mapping DRA-1980 shipped; no new window, no new button.
- **No send before the notice is seen**, as DRA-1980: `OptIn` is written when the notice
  closes. A kill or crash before then writes nothing; the profile stays legacy off, sends
  nothing, and sees the notice next launch.
- **Turn off stops sends at once.** On the notice: `Decline` (flag set, `OffByChoice` true,
  nothing armed). On the toggle: `SetEnabled(false)` keeps its disarm-before-save order; it
  now also sets `OffByChoice`. The existing tests stay and gain the key.
- **Unchanged and asserted unchanged:** an isolated profile never sends and never sees the
  notice; the harness can still only script a decline (and a scripted decline writes
  `OffByChoice = true`, so E2E profiles never flip on later); a `NoEndpoint` build spends
  nothing; re-enabling mints a fresh id; the delete action.

**Payload frozen.** `PayloadKeys`, `Payload`, `PayloadFor` and `TelemetrySender`'s body are
not touched. Reviewer refuses a diff to any of them. The new key never rides the wire.

**Words.** Every changed sentence lives in `UI.Shared/TelemetryCopy.cs`: the legacy-off
sentence above, and the Options caption if it still says a past "Not now" stays off.

**Requirement text.** `docs/v2/telemetry.md`: amend TEL-001 in place *"as amended by
DRA-2010 (Founder, 2026-10-18)"*: a past "Not now" is no longer final; it becomes on through
the one-time notice; only an off chosen on v2.0.7+ (notice Turn off, toggle, delete) is final.
Strike the "a past 'Not now' is still final" clauses (around lines 55–66, 476, 628, 667, 1016)
the same way DRA-1980 did, and record the fourth key and the v2.0.6-window decision.

**What's new.** One v2.0.7 entry: telemetry is now on by default **for every install**,
including anyone who said "Not now" before; they see a short notice once, before anything is
sent; closing it keeps it on, Turn off turns it off for good; the three fields and what is
never sent; the Options path by its real label (`Options → Behavior → Help improve EQBuddy`);
turning it off deletes the id; and that anyone who turned it off in v2.0.6 is asked once more
(the §1 sentence). No reporter to credit (Founder order).

**Tests, prove-failed.** `TelemetryHeartbeatTests`: every row of the §1 table plus
`OffByChoice` true/false → its outcome, each mutated once; a legacy-off profile sends nothing
before the notice closes; notice Turn off and toggle off both write `OffByChoice`, each pinned
on its own; `OptIn` clears it; isolated / scripted / `NoEndpoint` unchanged.
`TelemetryCopyTests` pin the cohort sentence to the legacy-off case only. E2E dump word if
`Word(PromptDecision)` changes. Shots: the notice in its legacy-off form (`shoot.ps1`,
Solarized once).

**V-level:** V2 (affected suites + `check.ps1`), then CI's two required checks.
