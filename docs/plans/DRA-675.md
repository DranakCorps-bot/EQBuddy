## 1. What happened, and what is actually being changed

v2.0.2: Reviewer PASS on DRA-660, the Founder's go already given ("ship it when the
review passes"), and the release still stalled — the interactive Claude Code
session's auto-mode classifier refused `release.ps1` as a production deploy and
refused writing its own allow rule. The GO existed; the EXECUTION had no seat.
It shipped at 11:02Z only after the Founder typed the allow rule himself (§5),
which is the exact founder-level keystroke this card exists to remove.

**What does NOT change:**

- **The GO stays the Founder's** (consequence item 2). Nothing here lets an agent
  decide to release. What changes is the GO's FORM: a conditional go written on the
  card ("ship it when the review passes") is a go, read for meaning per the
  2026-09-30 standing rule — it does not have to be re-typed at the moment of
  release. **But it is bound to a version and a reviewed commit** (§7 condition 2):
  it covers the tree the review passed, and is never cited against a later tag.
  A seat assignment or a Reviewer PASS is not a go, and the go is never "delegated"
  (§7 condition 4).
- **Signing stays unconditional.** `release.ps1` still throws unless every artifact
  is `Valid` and timestamped. No bypass, no `-SkipSign`, no warn-and-continue.
- **Fable's release review still precedes the go** where CLAUDE.md requires it; the
  release-review card is where the go is recorded.
- **An agent never grants itself a permission.** The allow rule is a Founder act.

## 2. Measure first (D1's first step, before anything is built)

Hypothesis, labelled as one: a Paperclip-dispatched `claude_local` seat does not run
under the interactive auto-mode classifier, so the refusal on v2.0.2 may not recur
on the seat at all — or it may, with a different permission prompt. D1 starts by
running the release script's **argument-refusal path only** from the seat:
`pwsh -NoProfile -File scripts/release.ps1 -EvolvedLocal -Tag x` throws on its
first lines (`-EvolvedLocal refuses -Tag`) before anything is built, tagged or
published. (A real tag, even a probe one, would publish — never do that.) That call
tells us whether the seat's permission layer lets the command shape through. Paste
the result on the card. **This probe clears nothing on its own** (§7 condition 1):
it shows the seat reached a throw, not that the permission layer accepts the live
string `release.ps1 -Tag vX.Y.Z` — and the v2.0.2 refusal was on that live string.
The run prints which adapter ran it. The allow rule's exact text and FILE PATH
(which settings file the Sr Executor seat actually reads — a user-level
`~/.claude/settings.json` would grant every Claude seat on this PC, which is wider
than the card allows) are D1's to measure and write down, not to guess.

## 3. D1 — the instrument and the procedure (one PR)

1. **`scripts/release-verify.ps1 -Tag vX.Y.Z`** — the post-release check, so "it
   shipped" is an observation rather than an exit code (trap 28, and CLAUDE.md's
   "a silent failure is not proof nothing happened"). It asserts, and prints each
   as its own row:
   - the tag exists on `origin` and points at the commit the run started from;
   - `gh release view vX.Y.Z` exists, is not a draft, and carries the expected
     assets;
   - the OneDrive file exists with a timestamp after the run began, and its
     **sha256 equals** the GitHub asset's and `dist\`'s;
   - `Get-AuthenticodeSignature` on every shipped artifact is `Valid` **and** has a
     `TimeStamperCertificate`.
   Exit non-zero on any row. **`-selftest` with prove-fail mutants** in the same
   commit (trap 34/78): a missing tag, a sha mismatch, an unsigned file and an
   untimestamped one each redden it. Wired into `check.ps1` (selftest only).
2. **`docs/ops/release-seat.md`** + a fifth row, **Release**, in
   `docs/ops/pc-change-runbook.md` (Sr Executor only). The procedure the seat runs
   on a release card:
   1. Read the card: a Founder go naming the version and the commit of the latest
      Reviewer PASS; `origin/main` equals that commit; Fable's release review
      recorded, or a Founder override that says it has not happened. Missing any →
      stop, comment, hand back to Planner. Never infer a go (§7 conditions 2–3).
   2. `git pull`; re-read `HANDOFF.md` for holds (a release hold binds).
   3. Preflight: `az account show` succeeds. If not → file/raise the Founder card
      "Founder: run `az login` (one line)" and set the release card `blocked` on it.
      This is the only human step, and it is surfaced as a card, not discovered
      three minutes into a build.
   4. `pwsh -NoProfile -File scripts/release.ps1 -Tag vX.Y.Z` (from `pwsh`, trap 27).
   5. `pwsh -NoProfile -File scripts/release-verify.ps1 -Tag vX.Y.Z`; paste output.
   6. Post only the reporter replies already WRITTEN on the card and marked routine
      signed thread replies — after re-reading `HANDOFF.md` again, signed
      `— Dranak (Claude Code)`. The seat composes nothing: no announcement, no new
      reply (consequence item 3; §7 condition 5).
   7. Close the card with the evidence.
   **HARD STOP:** a failed `release.ps1` is never retried, blind or otherwise, by the
   seat. Run `release-verify.ps1` to see what DID happen (tag? release? OneDrive?),
   paste it, and hand to Planner. A published release is not revertible — family
   widgets offer it within 6 hours (`release.ps1`'s own note).
3. **The allow rule, as text the Founder pastes** — exact rule, exact file, one
   command scoped to `scripts/release.ps1 -Tag v*` and `scripts/release-verify.ps1`,
   nothing broader, and in a file only the Sr Executor seat reads. If the only rule
   that lets `-Tag` through is wider (a user-level settings file every Claude seat
   reads, or a blanket production-deploy allow), D1 hands back to Planner — it is
   never widened to make D2 green (§7 kill criterion). D1 writes it into
   `release-seat.md`; D1 does NOT write it into any settings file.
4. **CLAUDE.md + DECISIONS.md:**
   - Consequence item 2 becomes: *"The release go. Still the Founder's, and still
     the one hard gate — but it is a decision, not a keystroke: the go names the
     version and the reviewed commit, may be conditional on that review ('ship
     v2.0.2 when the review of f9e266a6 passes'), and is recorded on the release
     card. EXECUTION is the release seat's (`docs/ops/release-seat.md`); the
     Founder is never asked to run the script. A seat assignment or a Reviewer
     PASS is not a go."* The word "delegated" does not appear (§7 condition 4).
   - The Commands block's "Releasing is `release.ps1`… Run it via `pwsh` from Bash"
     keeps the command and adds: run by the release seat on a card, verified by
     `release-verify.ps1`.
   - "Hold releases until David explicitly says ship" stays; append "(a go on the
     release card naming the version and the reviewed commit is explicit)".
   - `DECISIONS.md` appended entry: what changed, the default it could have gone
     (keep the go per-release and typed), the Founder's quote as authority, DRA-675.
     Append-only, explicit UTF-8 (trap 60).

Done bar for D1: PR merged on Reviewer sign-off + both required checks;
`release-verify.ps1 -selftest` green with every mutant shown red on the card;

## 7. Challenger conditions (DRA-676, PROCEED-WITH (C1), 2026-10-01)

Folded verbatim in substance from the walk; Planner adopts all five and the kill
criteria. The walk's alternative (leave item 2's wording, change only the Commands
block) is answered by condition 2: the reword survives, but a go is bound to a
version and a commit, so it can never become a citation of an old card.

1. **A §2 result clears only the exact string executed, on the adapter that runs
   D2.** D2 does not publish until that seat has shown the permission layer accepted
   `release.ps1 -Tag <version>`, or the Founder has pasted an allow rule whose text
   covers that live string. A green `-EvolvedLocal -Tag x` is not clearance.
2. **The go names a version and the commit of the latest Reviewer PASS.** (The walk
   named `f9e266a6` for v2.0.2; v2.0.2 has since shipped at exactly that commit, so
   this binds D2b.) If `origin/main` is anything else, D2b stops. A standing
   sentence with no commit bound is not a go.
3. **Fable's release review, or a Founder override that says it has not happened**
   (CLAUDE.md, "Fable reviews the release BEFORE David is asked"), is recorded on the
   release card before D2b. Reviewer PASS on DRA-660 is not that review.
4. **The CLAUDE.md reword never says the go may be "delegated."** "A decision, not a
   keystroke" is the wording; a seat assignment is not a go.
5. **Step 6 posts only replies already written on the card and marked routine signed
   thread replies.** The seat composes no release announcement (consequence item 3).

**Kill criteria.** Hand back if the only workable allow rule is wider than one script
on the Sr Executor seat. If condition 2 or 3 fails on a release card, ship nothing
and re-cut the go. (The walk's "abandon D2-as-v2.0.2" arm is spent: v2.0.2 shipped

signing credential, stop: that is the Founder's step (DRA-679 replaces it).
