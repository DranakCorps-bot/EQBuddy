# DRA-723: the pre-release PR gate

route: routine (one doc step in `docs/ops/release-seat.md`; the instrument is PR #1013)

**Founder, 2026-10-01 7:45 PM CT:** *"The EQBuddy sweeps need to catch these things."*

## What happened

PR #992 (DRA-638, #710) was signed off by Reviewer on 2026-10-01 01:51Z and left as a
draft whose body said **"DO NOT MERGE before `v2.0.2` is tagged."** v2.0.2 was tagged.
Then v2.0.3 was tagged, and the hold was never lifted or answered, so 2.0.3 shipped
without the fix. #992 merged at 2026-10-02 00:46Z, after the Founder noticed.

The DRA-636 queue sweep was a person reading `gh pr list`, and nothing in the release
procedure looked at the PR queue at all. A hold whose condition has already come true
looks the same as a hold that is still live.

## The change

1. **Instrument (routine, PR #1013, merges on Reviewer sign-off):** `scripts/pr-sweep.ps1`.
   It lists every open PR with draft, signed-off, required checks, mergeable and hold
   wording. A hold that names a release which is now tagged is an **EXCEPTION** until a
   comment dated after the tag says `HOLD LIFTED` or `STILL HELD: <reason>`.
   `-Release vX.Y.Z` is the gate mode. It is read-only, and `-SelfTest` is in
   `check.ps1` and CI.
2. **Rule (this PR, C5):** a new step 2 paragraph in `release-seat.md`. The release seat
   runs `pr-sweep.ps1 -Release vX.Y.Z`, posts the output on the release card, and stops
   unless it prints `GATE: PASS`. That means every open PR is merged or excluded with a
   reason, and none is an EXCEPTION. On FAIL the card goes to Planner. The seat never
   writes an exclusion reason itself.
3. **Every sweep:** the DRA-636-style queue sweep (Reviewer) runs `pr-sweep.ps1` without
   `-Release` each pass and posts the table. Exit 2 (EXCEPTION) is a finding, never
   silence.

## Why it is shaped like this

- **Exclusion needs a reason, and READY does not count as one.** A signed, green PR that
  is sitting is exactly the case being fixed. Either merge it before the tag, or write
  why it waits.
- **An `-Exclude` argument cannot cure an EXCEPTION.** Only a comment dated on the PR can.
  The cure has to live where the next reader of that PR will see it.
- **This tightens a gate and loosens nothing.** It adds one refusal before `release.ps1`.
  Signing, the Founder's GO (consequence item 2) and the HARD STOP are unchanged.

## Out of scope

Wiring a refusal into `release.ps1` itself. That script is on the signing path and has
its own guards, and the seat procedure is where the other preconditions already live.
If the seat ever skips step 2, that is the case for wiring it in, as a separate card.
