Founder-authored card, 2026-09-24. The page at `site/` was written while
Evolved was mid-build and reads as vision doc + status report + architecture
tour. The card's direction: cut it to a ~5-section player-facing product page.
**Subtraction first; add almost nothing.** This plan declares one
implementation slice (D1) plus a one-line release-day rider (D2).

## §1 What the page is today, measured

`site/index.html` is 42,348 B: hero + 9 numbered sections + closing —
tray story (5 steps, 5 GIFs), Guide, Roadmap, chain, surfaces, feature tour
(6 cards), deep dive (5 articles incl. a 7-row scorecard table), principles,
"Today, honestly", closing quote. 23 committed assets (18 stills + 5 clips),
every one pinned to a recipe in `LandingSiteTests.Manifest`.

## §2 The constraints that survive every cut (executor must-list)

1. **`LandingSourceClaimsTests`** — `site/index.html` is a registered surface
   with `MustEnumerateDumps: true` and both values lines required, **in one
   paragraph, not scattered bullets**. The footer disclosure paragraph
   ("EQBuddy reads what the game writes on your own PC — your /log, and the
   /outputfile dumps you ask for. It never reads game memory, never phones
   home, and never measures other players.") is kept verbatim. Hero trust
   pills may shrink or quieten but are additive to that paragraph, never its
   replacement.
2. **`LandingSiteTests` manifest pairing, both directions** — every picture
   cut from the page deletes its `Manifest` row in the same commit; every
   surviving picture keeps its row; the cut files are deleted from
   `site/assets/`. **No new captures.** Every image the new page draws is an
   already-committed asset, so the illustration lock is satisfied without a
   Windows shoot run. (If the executor judges a new hero capture is needed,
   that is a stop-and-escalate — it re-opens shot staging and the manifest.)
3. **Untouched arms of `LandingSiteTests`**: fonts committed + cmap coverage
   of the page's prose, no third-party requests, `shoot.ps1` default theme ≠
   BlueGrey assertion. The new copy must stay inside the webfont's cmap
   (plain punctuation; the page already uses curly quotes — reuse the
   glyph set already on the page).
4. **DRA-69 Ko-fi support link** stays (quiet, as today).
5. **Values-adjacent copy** ("no party meter", "never measures other
   players") survives in the trust section — it is the differentiator, and
   `TheValuesLinesAreStillRequired` enforces the footer half.
6. **License split stays stated**: published 1.x MIT; Evolved proprietary.
   One quiet line each, in the download section and footer — not a section.

## §3 The one truth decision — the Download CTA (default, logged here)

There is no Evolved artifact yet: `release.ps1` + `evolved-channel-guard`
hold the 2.x channel shut, and the release go is the Founder's gate. The card
asks for a "Download EQBuddy Evolved" hero CTA *and* forbids claiming
unfinished work as shipped. Default resolution, could have gone the other way:

- **Pre-tag (what D1 ships):** primary CTA **"Download EQBuddy"** →
  GitHub Releases, with the quiet line under it reading
  `Free · Windows · Local-first · No account required` and one sentence in
  the download section: today's download is 1.x (MIT); Evolved v2 is the
  page you are reading about and arrives as its own release.
- **At the v2 tag (D2, the release-day rider):** the CTA label flips to
  "Download EQBuddy Evolved" and that sentence drops — a one-line diff that
  rides the release PR, listed here so the SIGN covers it.

- **KPI band:** quests-tracked and items-cataloged tiles stay (rounded copy:
  "1,173 quests · 11,196 items" or the card's "1173+/11000+" shape). The
  **downloads tile is cut** — it counts 1.x installer downloads and on a
  launch page reads as Evolved traction ("careful with download counts",
  read strictly). The **max-concurrent tile and every "Telemetry not live
  yet" string are cut**, plus the `maxConcurrentUsers` special case in
  `landing.js`. `metrics.json` keeps its shape (other consumers unknown);
  the page just stops drawing two keys.

## §7 Slices, verification, acceptance

**D1 (Sr Executor, one PR):** everything in §3–§5 except the CTA flip.
Files: `site/index.html`, `site/assets/css/landing.css` (dead selectors
pruned only where their markup died; no restyle), `site/assets/js/landing.js`
(KPI arm), deleted assets, `tests/EQBuddy.Tests/LandingSiteTests.cs`
(manifest rows), new `docs/HOW-EQBUDDY-WORKS.md`. No app code, no
`WhatsNew.json` (nothing player-noticeable ships in the app).

**D2 (release-day rider):** the §3 CTA label flip + sentence drop, inside
the v2 release PR. Declared here so it needs no second SIGN.

**Verification (V1):** `dotnet test` on the two landing suites +
`LandingSourceClaimsTests`; open the page locally (file:// has no metrics
fetch — check the KPI band's static text path) and at a phone width;
grep-level checks the executor asserts in the PR body:
- exactly five `<section>` blocks between hero and footer's main,
- zero occurrences of `Telemetry`, `roadmap`, `Coming for Evolved v2`,
- zero occurrences of "Download EQBuddy Evolved" (that string is D2's),
- footer disclosure paragraph byte-identical,
- manifest count equals drawn-asset count (the tests prove it; the PR body
  states the new number).

**Acceptance = the card's 30–45s test**, checked as: a first-screen reader
gets what-it-is + why-useful (hero), the four player questions (S1), what it
looks like (every section is screenshot-led), how Evolved differs (S3 + S4
trust statements), where to get it (hero CTA + S4) — with no roadmap, no
architecture, no development history anywhere on the page.

**Out of scope, restated from the card:** app functionality, refactors,
brand redesign, invented features or claims, new sections, Play Console /
signing / Founder mailbox, any release action.
