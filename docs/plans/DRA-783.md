## 2. The two facts that shape the plan

1. **shields.io cannot sum.** A dynamic-JSON badge over the GitHub API joins
   multiple matches with commas; it does not add them, and cannot filter out
   `.sha256`. The sum has to be computed by something we own and published as
   one number. The worker is the thing we own that already publishes the
   README's numbers, already runs a 10-minute cron, and already has a database.
2. **"Last 30 days" needs history GitHub does not keep.** The API gives
   cumulative totals only. Until 2026-10-28 the answer is exact for free: every
   Evolved download happened inside the window, so *downloads in the last 30
   days = downloads since 2.0*. From 2026-10-28 on, the window needs the total
   as it stood 30 days earlier, which only a daily snapshot can supply — and
   snapshots start the day D1 deploys (S). For days between 2026-10-28 and S+30
   there is no honest number; the worker publishes `null` with the reason and the
   badge says so, rather than guessing.

## 3. D1 — worker (`DranakCorps-bot/eqbuddy-telemetry`), route: hard

- **Fetch.** Once an hour inside the existing cron (minute bucket 0), GET
  `api.github.com/repos/DranakCorps-bot/EQBuddy/releases?per_page=100`
  (unauthenticated: 24/day against a 60/hour limit). Admit releases whose tag
  matches `^v2\.` and that are not drafts; sum `download_count` over assets
  whose name does **not** end in `.sha256`. Any failure (non-200, unparseable,
  zero v2 releases) writes nothing and keeps the previous figure with its
  as-of; it never writes 0.
- **Store.** Migration `0005_downloads.sql`: one row per UTC day, the latest
  cumulative total seen that day + its as-of. No install id, nothing about a
  player — it is a number about GitHub.
- **Publish** in `metrics.json` (schema stays 1; additive):
  ```json
  "downloads": {
    "since": "2026-09-28", "sinceTag": "v2.0.0",
    "total": 1343, "last30d": 1343, "last30dNote": null,
    "asOf": "2026-10-02T11:00:00Z"
  },
  "usageHours": { "...": "...", "allTimeRounded": 3019 }
  ```
  `last30d` = `total` while `since` is inside the window; then `total` minus the
  snapshot 30 days back; `null` with `last30dNote` naming the first day a figure
  will exist when that snapshot is missing. `allTimeRounded` exists because a
  badge over `allTime` would print "3019.33" (shields cannot round). Both get
  `definitions` entries saying exactly the above, including "fetches of the
  installer and portable zip — a re-download, an update and a bot all count".
- **Say it.** The worker's README names its first outbound call (GitHub's API,
  and why). `landing-telemetry.ps1`'s trim already drops unknown keys; its
  selftest is not touched.
- **Done bar:** vitest rows for: sha256 excluded; v1 tags excluded; drafts
  excluded; a failed fetch keeps the old figure (and never writes 0); `last30d`
  equals `total` inside the window, equals the difference after it, and is
  `null` with the note in the gap; `allTimeRounded` rounds half-up. Prove-fail
  the sha256 and the never-zero rows. Deployed, and `metrics.json` shows
  `downloads.total` within a fetch of a hand sum from `gh api`.
- **Stop seam:** if the deploy needs a Cloudflare credential this seat does not
  hold, stop and hand to Planner — do not ask for the token in a comment.

## 5. Decisions taken here (logged, Founder may veto)

- **Hours are labelled "estimated"**, not "played", unqualified: the worker's
  own definition says estimated, and the card says no estimate presented as
  measured. EQBuddy running is also not quite the game being played; the
  sentence says "running".
- **`.sha256` fetches are excluded.** Default could have been "all assets";
  excluding is the honest count of installer downloads.
- **The installs row goes, as asked.** Default could have been "keep both"; the
  Founder named the swap. The number is not lost (metrics.json, live report).
- **The gap is `null`, not a back-fill.** No per-day split of pre-snapshot
  downloads is invented.
